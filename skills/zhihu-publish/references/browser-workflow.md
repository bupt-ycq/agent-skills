# 知乎浏览器排版经验

以下行为来自 2026-11-04 的实际发布。作为排查线索使用，不保证以后 UI 不变。不复用当时的草稿 ID、账号、CSS 哈希类名或已过期图片链接。

## 导入正文

- 实测路径是工具栏“导入”→“导入文档”→弹窗“点击选择本地文档或拖动文件到窗口上传”。第一层菜单只打开弹窗，最后一个控件才触发文件选择器。
- 文件选择器事件须在点击真实上传控件前订阅。使用当前工具文档支持的 API，并立即处理超时异常，避免未处理的异步异常中断会话。
- 原生 Markdown 导入保留了正文、公式、表格、代码和标题，但标题层级可能改变；正文第一行 H1 不会自动填入文章标题框。可以先移除正文中的重复总标题，再单独填写标题。
- 实测表格里的 `$...$` 没有转成公式。简单维度改为清楚的普通文本，如 `N_q × d`；复杂表内公式放到表格外独立展示，不发布裸 LaTeX。
- 编辑器是富文本控件，直接 `fill('')` 曾未清除 Draft.js 内容。确实需要替换**本任务刚创建的正文**时，聚焦正文、全选、删除，再检查是否已空。保留本地稿，不把全选删除用于未知旧稿。
- 不在未确认光标位置时插图。曾在代码块中按文档末尾快捷键后，图片仍插入代码中间。应使用明确正文位置或占位段落，并检查结果。

## 配图

- Markdown 内嵌 `data:image/png;base64,...` 在本次导入中全部上传失败，不能因为离线 HTML 可显示就假设知乎可用。
- 通过知乎原生图片上传控件上传本地 PNG。工具栏“图片”会先打开图片库弹窗；“本地图片上传”的实际可点击区域需观察当前 UI/DOM，文字节点不一定触发文件选择器。
- 批量上传后检查成功数量。此次 10 张图首次有 2 张失败，点击“批量重新上传”后成功。成功后还需要“插入图片”。
- 长文可先把本次图片批量上传至本任务草稿，读取编辑器 DOM 已显示的图片引用，确认顺序与原图对应，再把最终正文中的图片地址替换为这些已上传引用，重新导入。仅在确实能确认映射并保留完整本地稿时采用；否则逐图定位上传。
- 本次已上传图的知乎引用可通过 Markdown 再导入，发布预览转换为知乎托管图片。草稿 DOM 地址可能带签名和有效期：只作当前排版临时引用，不当作永久资源、不放进可分发备份或 skill。永久备份使用本地图片。
- 导入后核对最终图片总数、顺序、尺寸与图注，排除重复图片、失败占位和多余临时插图。

## 公式和懒加载

- 此次原生 Markdown 导入生成了带 `data-tex` 和 `data-eeimg` 的公式 DOM，公式源保留下来。只可用只读 DOM 检查源文本、数量和渲染情况，不修改这些属性或应用内部状态。
- 在编辑器和阅读预览里，未进入视口的公式可能先显示 LaTeX，占位图片也可能为空白。仅凭全页 DOM 中已渲染 SVG 的数量少，不能判定公式丢失。
- 滚动到目标段落后重新观察，等待页面正常渲染再截图。此次分块合并公式从裸文本加载为正确矩阵/求和式，图片也随后出现。
- 检查长 `aligned`、分式、上下标、框公式，以及相邻行内公式。确认代码换行和缩进仍完整。
- “预览”→“电脑预览”会打开独立标签页；预览地址不等于公开文章地址。不要把含 `/preview` 的地址当作发布结果。

## 保存、发布与交付

- 刷新前等待“草稿保存中”结束。刷新后先等数据载入，短暂空编辑器不代表草稿丢失。
- 发布时按钮可能在“发布中...”停留一段时间。不要连续重复点击或立即刷新。等待返回明确结果，必要时检查当前页面的错误提示。
- 本次完成标志是“发布成功”弹窗，同时进入不含 `/edit` 或 `/preview` 的文章页面。
- 发布成功弹窗还含“转发到想法”“同步到圈子”“私信分享”。这些是额外动作，不属于普通发布授权。
- 在确认成功的同一操作阶段保存页面截图，记录文章 URL，按工具要求标记交付标签页并提交完成摘要。不要在成功后继续无目的探索账号页面。
