# 有道云备份与私有仓库同步

把当前云端内容完整导出，保留已有本地和仓库侧修改，并给出可验证的同步结果。仅执行本次用户要求的范围：安装、登录配置、本地下载、GitHub 推送可分别进行；暂停上传后，完成登录不代表恢复上传。

## 入口与个人配置

- 已有部署时，先核实用户指定的项目目录、导出目录、实际登录账号和私有仓库；可用 [配置示例](references/local-profile.example.md) 记录非敏感设置。个人配置放到仓库外，不提交历史清单、笔记路径或运行状态。
- 首次安装、Python 兼容问题：读 [installation.md](references/installation.md)。
- Cookie 过期、本机会话导入、GitHub 账号或授权问题：读 [authentication.md](references/authentication.md)。不要把账号授权当成已完成，必须通过真实接口核实。
- 下载和推送的具体步骤、脚本参数：读 [sync-workflow.md](references/sync-workflow.md)。

## 同步顺序

1. **确认范围和状态。** 读取导出配置；仅检查必要的本机登录状态。若推送已获授权，确认 GitHub 的实际账号、目标仓库、默认分支及 `private=true`。不要凭插件连接状态推断本机 CLI 身份，也不要把沙箱断网造成的 `gh auth status` 失败当成令牌过期。
2. **保存本次之前的状态。** 在导出目录之外创建独立运行目录。保存旧云端清单、本地原始导出快照以及远端提交号；快照是后续三方合并的基线。第一次没有旧清单时，跳过旧路径清理，不猜测哪些文件应被删除。
3. **下载并核对。** 用项目自己的虚拟环境启动导出；日志留在运行目录，聊天只报告数量和错误类别。用 `scripts/sync_state.py inventory` 读取最新清单，再用 `audit` 核对每个云端文件和图片、附件的本地链接。
4. **处理明确的异常。** 项目会捕获单篇失败后继续运行，退出码 0 不等于全部成功。按失败文件 ID 有限重试；确认转换失败的原件已保存。空白输出要与云端原件核对，不能直接认定丢失。缺文件、目录清单截断、同名覆盖或未解决的转换错误必须先解决，再推送。
5. **按要求整理旧路径。** 需要反映云端移动、改名和删除时，用 `archive` 先生成计划，再 `--apply`：仅归档旧清单证实已过时、内容仍与本次快照一致、且不再被当前笔记引用的文件。归档位于导出目录和待推送仓库之外。不能把来源不明的文件当成历史垃圾清除。
6. **追加到私有仓库。** 从最新远端提交建立干净工作区。用 `scripts/prepare_git.py` 合并新导出与仓库已有修改；保留 `.gitignore` 等仓库自有文件。对双方修改用快照做三方合并，冲突时停止推送并处理具体文件，不能直接覆盖或强推。
7. **验证推送。** 推送前再次验证 owner、私有性和远端分支；普通非强制 push。随后核对远端提交 SHA、树未截断、文件数及私有性。成功后才更新“最近成功同步”的状态指针。仅提供当前用户能直接使用的结果，不输出 Cookie、令牌或笔记正文。

## 经过实际使用确认的细节

- 从项目目录启动 `pull.py`；其配置定位依赖当前工作目录。默认图片只保存本地，`smms_secret_token` 留空，`is_relative_path=true`。
- `cookies.json` 中 `YNOTE_CSTK` 必须放第一项。模板值 `**` 不代表已登录。
- 原依赖 `requests==2.22.0` / `urllib3==1.25.11` 无法在本机 Python 3.12 导入。按安装参考做最小兼容调整，不随意全面升级。
- 新版 JSON 无序列表的 `ll` 可能为 `null`；按顶层列表处理，保留正常嵌套级别。
- 图片文件名可能含 `(1)` 等括号。脚本使用配对括号解析 Markdown 链接，不能用遇到第一个 `)` 就停止的正则误报断链。
- GitHub 侧曾修改过笔记内容。原始导出与仓库内容不必逐字相同；应保留仓库侧修改，尤其不能重新引入已去除的凭据。
- 导出文本可能是 CRLF 且带尾空格。不要因 `git diff --check` 的排版警告重写用户笔记，也不要把全文差异输出到聊天。

## 交付

简要报告本地目录、云端清单数量、增量变化、异常处理或归档情况。推送时附私有仓库链接和已核实的提交短 SHA。部分失败就明确说明剩余项；没有用户要求，不创建定时任务或自动追加推送。
